# 演示脚本（3 分钟版 + 5 分钟版）

> 最后更新：2026-09-14 ｜ 用于决赛 Demo、录制视频、自测闭环
> 录制前确认：地址栏无 Secret、无 devtools、无 `.env` 文件入镜。

---

## 零、录制/演示前 5 分钟准备

1. 打开 `https://<你的域名>/api/health`，确认 `ok: true`、`credentials: true`。
2. 打开首页，**先跑一次**演示问题 —— 结果会缓存 30 分钟，现场不用等。
3. 关掉其他标签页、通知、微信弹窗。
4. 分辨率 1920×1080，浏览器缩放 100%，隐藏书签栏。
5. 麦克风试音；建议系统音 + 旁白双轨，后期降噪。

**推荐演示问题**（都是真实可检索的）：
- `30岁从大厂裸辞去做独立开发，值得吗？`（触发一手经历缺口）
- `月薪8000该不该辞职考研？`（触发条件缺口，severity 0.84，最直观）

## 一、3 分钟版（评委 Demo，总时长 2:50）

| 段 | 时间 | 画面 | 旁白（可直接照读） |
|---|---|---|---|
| 1 | 0:00–0:15 | 封面 → 首页首屏 | 「这是二号知乎。知乎上同一个问题常有几十个回答，但你看到的只有排序，没人告诉你这些回答到底在争什么，以及**他们共同没回答的是什么**。」 |
| 2 | 0:15–0:30 | 输入问题，点「召集分身」 | 「我提一个真实的问题：月薪 8000 该不该辞职考研。」 |
| 3 | 0:30–0:50 | 看山舞台：接入 → 路由 → 检索 → 比对 | 「看山先判断这属于什么类型的问题，再从分身库里选出该回答的视角。每个分身用**不同的检索词**去知乎开放平台取真实回答作为证据。」 |
| 4 | 0:50–1:15 | 分身卡片错峰入场，展开证据 | 「注意每张卡下面的来源：标题、作者、赞同数、原链接，全部来自知乎真实接口。**我们不用假数据** —— 接口失败就如实报错。」 |
| 5 | 1:15–1:40 | 橙色缺口区出现 | 「这是本作品最不一样的一步。四个分身各自答完之后，系统做了一次交叉比对，指出它们**共同缺失的那一块**：问题限定了月薪 8000 这个前提，但没有任何一条一手经历是在这个条件下发生的。」 |
| 6 | 1:40–2:00 | 真人候选 → 点「邀请真人」 | 「缺口被翻译成一个具体的人：需要什么样的人、为什么是他。候选来自刚才那些真实回答的作者 —— **问题问对了，才能把有经验的人钓出来**。」 |
| 7 | 2:00–2:20 | 跳 `/fill` 填真人补充 → 返回工作台 | 「现在真人接管。补充内容会被标记为『真人补充』，和 AI 草稿区分开，一起并入最终稿。」 |
| 8 | 2:20–2:35 | Human Mesh 关系图长出新边 | 「补充完成后，Human Mesh 关系图长出了新的节点和边。问题、分身、关键词、真人、回答 —— 关系全部可见、可追溯。」 |
| 9 | 2:35–2:50 | 搬运面板 + 结尾封面 | 「关于发布，我们必须说清楚：**知乎开放平台没有写入接口**，54 个文档条目全是只读。所以我们不承诺一键发布，只把整理好的正文和来源放进可复制面板，由用户自己到知乎发布。我们把 AI 的效率，接在真人的可信度上。」 |

## 三、必须出现的画面（评审关注点）

- 真实知乎链接与作者名（证明数据来自真实接口，不是编造）。
- 橙色缺口区（创新点⑤，权重最高）。
- 真人补充前后的 Mesh 对比（完成度）。
- 发布边界说明（合规，避免扣分）。

## 四、答辩高频问题准备（2 分钟）

| 可能被问 | 回答要点 |
|---|---|
| 和直接问 AI 有什么区别？ | 单次 AI 只给一个视角；我们给的是**多视角结构 + 共同盲区**，每个视角都有可点击的真实来源。 |
| 数据从哪来？会不会编造？ | 全部走知乎开放平台真实接口；接口失败展示真实错误，页面没有假数据填充。见 `docs/api-audit.md`。 |
| 能直接发布到知乎吗？ | 不能，平台无写入接口。我们不做假按钮，改为可复制正文 + 真实编辑器深链。见 `docs/publish-path.md`。 |
| 额度够用吗？ | 热榜/直答各 100 次每天，结果按问题缓存 30 分钟，同一问题反复演示不重复消耗。见 `docs/prerequisites.md`。 |
| 为什么用直答而不是别的模型？ | 直答是知乎自家能力，与生态契合度高，且能把真实证据压缩成立场一致的草稿；失败时降级为检索摘要并明确标注。 |
| 刘看山素材授权？ | 仅在比赛授权范围内使用，赛后商用需另行取得知乎授权；几何为原创，未使用参考项目任何素材。 |
| 商业化？ | 缺口派单可以成为「问题 → 真人」的匹配层，对平台是更多有信息增量的回答。 |
| 和知乎官方 AI 的关系？ | 不是替代。我们用的是平台提供的直答能力，做的是它没做的「多视角比对 + 缺口派单」。 |

## 五、后期处理

- 关键节点打文字标注（「真实接口」「共同盲区」「Mesh 更新」），评委常静音看。
- 缺口出现的那 2 秒**留白**，不要配音乐高点 —— 让画面自己说话。
- 结尾 5 秒固定放仓库地址与 Demo 地址。
- 导出 1080p、码率 ≥ 8 Mbps；上传 B 站/YouTube 拿公开链接填进提交表。
