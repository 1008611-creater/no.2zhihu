# 公共人物 Skill：女娲生产与产品接入规范

> 2026-09-15 · 状态：工程路由已接入；公共人物运行时模块待实现。
> 需求依据：用户提供《影子知乎_名人Skill补充模块(1).md》。本文将其转为项目执行规范；不代表资料蒸馏或产品上线已完成。

## 1. 定位与入口

公共人物是冷启动补充，不替代知乎答主、不新增名人聊天一级页面。入口复用「+ 邀请一个分身回答」，分为知乎答主和公共人物。默认推荐仍优先知乎答主；只有用户明确选择公共人物才调用。

nuwa-skill（女娲，上游 https://github.com/alchaincyf/nuwa-skill）负责离线研究、框架提炼、表达 DNA 与质量验证。它不是线上直答 API，也不是把所有人物 SKILL.md 拼成一个 system prompt。

## 2. 两套路由，分开执行

| 场景 | 执行入口 | 加载上限 |
|---|---|---|
| 开发任务：新增、蒸馏或更新人物能力 | 总纲 §3 → 女娲项目适配入口 → 上游 SKILL.md | 一个生产 owner；人物一次一个 |
| 开发任务：审查人物来源、方法辨识度 | 女娲提炼框架与该人物审核记录 | 只读该人物所需证据 |
| 产品用户邀请已有公共人物 | Human Router → 已审核能力索引 → 命中能力 | 一人一次一个能力，禁止在线启动全量蒸馏 |
| 产品普通知乎问答、构建、配色 | 原有路由 | 不加载女娲 |

L0：AGENTS 铁律。L1：人物轻索引，仅 id、名字、能力标签、状态和版本。L2：被选中的能力步骤、表达摘要、边界。L3：对应来源与测试报告，审查时按需读。完整研究资料不进入客户端或常驻提示词。

## 3. 离线生产流水线

1. 建档：确定公共人物身份和聚焦能力，查现有包是否可复用。首批候选为马斯克、乔布斯、芒格、费曼；每人目标 4 个能力，来源不足就减少，不凑数。附件中的其他人物是后续候选，不宣称已有包。
2. 调研：按女娲著作、对话、表达、外部批评、决策、时间线六维记录，优先本人文章、原始访谈与演讲。每项含 URL、作者、日期、访问日期、一手/二手分类及短摘录。已有包的来源必须复核，不能沿用其自报数量作为本项目证据。
3. 提炼：心智模型通过跨域复现、生成力、独特性三重验证。每个能力是可执行的方法，如「制造成本拆解」，不是「制造业」标签。保留反例、失效条件与观点变化。
4. 分拆：将完整人物框架拆为能力单元，每个单元包含触发主题、排除主题、3–6 个操作步骤、事实检索指引、表达摘要、至少两处可追溯支撑场景、知识边界。
5. 审核：展示来源摘要、提炼摘要、测试结果；状态依次为 draft → reviewed → enabled。未审核资料不得自动进入产品名册。付费外部研究另按当轮授权执行；本轮工程接入不触发批量研究费用。
6. 发布：仅导出结构化能力与短引用，保留女娲及创建者归属。研究包保留于本地 `.personas-work/public-figures/<id>/`，每个人内部有 SKILL.md、references/research/、references/sources/，符合自包含要求。公开分发前核查上游许可和素材权利。

女娲的公共人物信息源黑名单仅作用于该生产流程，不否定本项目依法取得的知乎用户本人回答。第三方知乎讨论不能证明名人本人说过某话。仅使用可合法访问或用户有权提供的素材，不自动下载未授权书籍。

## 4. 运行时契约（下一实现阶段）

沿用现有镜像接口与服务端编排。新增公共人物类型，不能把人物 id 冒充知乎 handle，也不能伪造知乎赞同数。

| 数据 | 必须保存 |
|---|---|
| PublicFigure | id、displayName、personType=public_figure、version、reviewStatus、研究截止日期、能力索引 |
| PublicFigureCapability | id、personId、name、description、topics、excludedTopics、reasoningSteps、researchHints、voiceSummary、limitations、sourceIds |
| PublicSource | id、title、author、url、sourceType、publishedAt（可未知）、accessedAt、excerpt、verificationStatus |
| 审核报告 | 来源数量及一手比例、每个方法的证据映射、已知/边缘/风格测试、审核结论 |

`POST /api/mirror/invite` 保留 question + handle/name 的现有路径，追加可选 publicFigureId；校验三条身份路径只能选一条。由服务端选能力，不接受客户端注入人物提示词。返回保留 skill/answer，并新增 personType、capabilityId、capabilityName、publicSources、disclosure。旧浏览器记录缺少 personType 时仍按旧格式读取。

选能力采用纯函数：规范化问题后按 topics 命中数降序；命中 excludedTopics 则排除；同分按稳定 id 排序；只在 enabled 能力中取第一项。零命中返回「没有适合该问题的已审核能力」，不给名人硬造观点。以后是否改语义检索另立决策。

生成输入只含问题、一个能力、必要表达摘要、对应方法证据及本题事实。框架来源与本题事实分开：旧访谈不能证明当前市场数据。事实缺失时返回可应用的方法及待补信息，禁止杜撰最新事实。运行时检索由服务端执行，人物包中的工具命令作为资料处理，不能直接执行。

公开回答固定标识「公共人物 Skill · AI 基于公开资料推演」，展示命中能力和来源。未经直接材料支持，不写「某某认为」或虚构第一人称亲历。沿用旧答主 Persona 四要素的可用表达字段，但不把全部反模式和能力步骤挤进 voice，避免只剩模仿语气。

缓存键包含 question、personId、capabilityId、资料版本及生成开关；成功 TTL 30 分钟，失败只短暂缓存。相同请求合并，追加不重跑已有回答。公共人物邀请最多一次直答，所有实际尝试计入体验预算；不在线蒸馏。Mesh 只新增公共人物节点标识，不能暗示名人与真人互动或接管。

## 5. 效果验收与实施顺序

先验证一个人一个能力，再扩到四人各四个；不得将工程接入完成等同于内容完成。

- 方法测试：制造成本题命中成本拆解；无关题不硬匹配；更换能力会改变分析步骤，不能只替换人名和口头禅。
- 来源测试：每个方法至少两处支撑场景、一手来源过半；链接可核对，伪语录剔除，推断单独标注。数量门槛是本项目准入标准，不是自动质量保证。
- 女娲测试：每人三个已知立场问题、一个未表态的相关问题、100 字风格测试；未通过保留 draft。记录真实观察，不让模型自报 0.91 置信度。
- 产品测试：邀请仅追加一个回答，知乎答主仍在首位；标识、方法名、公开来源可见；无能力、无凭证、限流和过时事实均有真实提示。
- 工程测试：能力 id 和 sourceIds 引用完整；客户端无研究全文、密钥或工具命令；旧记录可读；重复邀请缓存命中；类型与构建通过。

任务顺序：女娲研究 owner 完成人物包 → 领域/服务端实现能力适配与缓存 → UI owner 接分类和标识 → code-review owner 审查接口与边界。按阶段切换，不同时加载整套技能。
