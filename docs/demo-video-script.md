## 一、先对齐：当前的信息架构

**两条主线**：提问（把问题问出来）与分身发现（看看这里住着谁）。

| 入口 | 路由 | 这一页在做什么 |
|---|---|---|
| 提问 | `/` | 输入问题 → 选答主 → 生成（`Step 1 · 选答主` / `你想听谁回答这个问题`） |
| 查看回答 | `/mirror` | 首轮作答 / 互相回应 / 看山发现的缺口 / 真人邀请 |
| 真人补充 | `/fill` | **提问主线的子页面**，从 `/mirror` 进入；写回后提示 `Mesh updated · 补充已写入` |
| 回答详情 | `/answer/[id]` | 单篇回答的证据与追问 |
| 分身发现 | `/personas` | 16 位答主名册；**点卡片开浮层**看四要素（不跳页） |
| 答主档案 | `/personas/[handle]` | 单人的领域 / 立场 / 语言节奏 |

## 二、录制前 5 分钟准备

1. 打开 <https://zhihu.cauai.fun>/api/health，确认 `ok: true`、`credentials: true`。
2. 打开首页，**先跑一次**演示问题（结果缓存 30 分钟，现场不用等）。
3. 关掉其他标签页、通知、微信弹窗。
4. 分辨率 1920×1080，浏览器缩放 100%，隐藏书签栏。
5. 麦克风试音；建议「系统音 + 旁白」双轨，后期降噪。

**推荐演示问题**（都在广场库里跑过，效果稳定）：

- `30 岁从大厂转行做独立开发，值得吗？` —— 会触发「缺一手经历」的缺口
- `读博六年没毕业，还要不要坚持？` —— 三位答主的立场反差最大

## 五、2 分钟问答准备（高频问题）

| 可能被问 | 回答要点 |
|---|---|
| 和直接问 AI 有什么区别？ | 单次 AI 只给一个视角；我们让你**指定具体的人**各答一遍（按本人的领域、立场、说话方式），再给出**共同盲区**，每段都有可点击的真实来源。 |
| 怎么保证「像这个人」？ | 人格由本人公开回答蒸馏成四要素（知道什么 / 怎么看问题 / 怎么说话 / 不装懂什么）；字数区间、句长、标点习惯也由人格决定，不再全站统一。生成后还有一道文风校验与「掉出人格」守卫（`lib/domain/voice.ts`、`lib/domain/answerIntegrity.ts`）。 |
| 数据从哪来？会不会编造？ | 回答的证据全部走知乎开放平台真实接口；接口失败展示真实错误。**检索不到对口证据时不硬写** —— 卡片会如实写「没有对口证据，这一段就不硬写了，等一位真人来补」。 |
| 能直接发布到知乎吗？ | **不能**，平台无写入接口（全部 54 个文档条目均为只读）。我们不做假按钮，只提供「复制正文 + 打开知乎问题页」，发布由人完成。见 `docs/publish-path.md`。 |
| 额度够用吗？ | 实测直答与知乎搜索各 **5000** 次、热榜 100 次/天；单次体验 ≤7 次直答，结果按问题缓存 30 分钟，反复演示不重复消耗。见 `docs/api-audit.md`。 |
| 为什么用直答而不是别的模型？ | 直答是知乎自家能力，与生态契合度高，且能把真实证据压缩成与人格一致的草稿；失败时降级为证据直引并明确标注。 |
| 刘看山素材授权？ | 仅在比赛授权范围内使用，赛后商用需另行取得知乎授权；几何为原创，未使用参考项目任何素材。 |
| 和知乎官方 AI 的关系？ | 不是替代。我们用的是平台提供的直答能力，做的是它没做的「多视角比对 + 缺口派单」。 |
| 商业化？ | 缺口派单可以成为「问题 → 真人」的匹配层，对平台是更多有信息增量的回答。 |
