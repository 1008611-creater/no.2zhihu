# 「搬运回知乎」的真实可行路径

> 最后更新：2026-09-15 · 结论来源：[api-audit.md](api-audit.md) 全量文档审计

## 一、审计结论（关键）

**知乎开放平台没有提供任何把内容写入知乎的接口。**

已核对全部 54 个文档条目，唯一带 POST 语义的只有 4 个，且都与发布无关：

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `https://openapi.zhihu.com/access_token` | OAuth 换取 token |
| POST | `https://developer.zhihu.com/v1/chat/completions` | 直答生成（读，不是写） |
| POST | `/api/v1/knowledge/search` | 知识库检索（读） |
| POST | `/api/v1/knowledge/files` | 上传文件到**知识库**，不是社区发布 |

响应里出现的 `PublishCount` 是**统计字段**，表示该账号历史发布数量，不是发布能力。
官方文档明确：发布相关字段、scope、token 撤销/刷新**未文档化**，不得猜测实现。

## 二、因此产品必须这样设计

**禁止**出现「一键发布到知乎」按钮或文案。这不是工程取舍，是事实约束。

正确叙事是「**AI 生成 → 人确认 → 人带走 → 人发布**」，且**带走的动作由本产品完成，发布的动作由人完成**。

## 三、可选路径（按推荐度排序）

### 路径 A：复制为知乎回答格式（推荐，Demo 采用）

用户点「复制」→ 剪贴板得到一段已排好版的 Markdown/纯文本，结构为：

```
（正文）

---
本回答由「二号知乎」整理，证据来自以下知乎回答：
· 《标题》 — 作者名  https://...
· 《标题》 — 作者名  https://...
```

用户自行打开知乎对应问题页粘贴发布。

- ✅ 完全合规，不触碰任何平台限制
- ✅ 保留了来源归属（官方硬性要求）
- ✅ 实现成本最低，Demo 一定能演示
- ⚠️ 多一次手动操作

### 路径 B：深链跳转到知乎编辑器

在复制的基础上，提供「去知乎回答这个问题」按钮，跳转 `https://www.zhihu.com/question/{id}`。

- ✅ 缩短用户路径
- ⚠️ 具体问题 ID 需从用户输入的问题链接解析；手输的问题无法定位
- 处置：仅当用户输入的是知乎链接时显示此按钮

### 路径 C：OAuth 读取本人内容做对照

拿到 OAuth 后，可以读取**用户自己**已有的回答列表与创作数据，用于：

- 展示「你的历史回答里，这个视角已经讲过」
- 计算贡献值

- ✅ 合规（本人数据只读）
- ❌ **仍然不能发布**

### 路径 D：导出为文件

导出 `.md` 文件下载。

- ✅ 适合长文
- ⚠️ Demo 里不如复制直观，作为附加选项

## 四、最终稿的归属标记（强制）

真人补充后的最终稿必须区分三种内容，界面上用不同色条标识：

| 标记 | 含义 | 颜色 |
|---|---|---|
| `ai` | AI 基于知乎证据生成 | 分身的身份色 |
| `human` | 真人补充，注明是谁 | green |
| `handed-off` | 已确认搬运 | blue |

## 五、代码落点

```ts
// lib/domain/handoff.ts
export function toZhihuDraft(mirror: MirrorQuestion): string
// 输出已排版的文本，包含正文 + 来源列表

export function zhihuQuestionUrl(sourceUrl: string): string | null
// 从知乎链接解析 question id，失败返回 null（不猜测）
```

`HandoffState` 已定义于 `lib/domain/types.ts`，字段 `note` 用于向用户如实说明
「本产品无法代你发布」。

## 六、入口位置（2026-09-15 修正）

**搬运是收尾动作，不是作答流程的一步。**

原先「把我的分身搬回知乎」面板挂在 `/mirror`（回答问题工作台）页面末尾，语义上错位：
用户在那里是**在做题**，不是**在决定发布**。已改为：

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `/mirror` 工作台 | 只留一条跳转链接「去我的 Mesh 搬回知乎 →」 | 搬运面板本体 |
| `/mesh` 我的 Mesh | `MineHandoffPanel`（跨全部历史问题的搬运清单）+ 统计区「N 篇分身回答还没搬回知乎 → 去搬回知乎」锚点 | — |

面板升级为**跨全部历史问题的搬运清单**：`history` 里每个跑完的问题各占一张卡，
标注状态（已发布 / 已打开知乎 / 可以搬运）、篇数、字数、来源归属数与答主名，
提供「只复制正文 / 复制正文并打开知乎问题页 / 我已在知乎发布」三个动作。

store 相应新增按 id 定位的方法（`markHandoffOpenedFor` / `confirmHandoffFor`），
因为清单里操作的是**第 N 个问题**，而不是当前 `mirror`——用无参版本会搬错对象。

手输的问题没有知乎链接，面板**只复制正文**并如实说明，不猜一个地址给用户（沿用原降级策略）。
