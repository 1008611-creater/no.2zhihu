# 影子知乎补充模块：名人 Skill 集群

> 模块定位：**公共人物预置 Skill 集群 / 冷启动与 Demo 增强模块**
>
> 产品优先级：辅助模块，不改变影子知乎主架构。
>
> 当前阶段价值：在知乎真人用户 Skill 蒸馏速度较慢、可用样本数量有限时，提供一批提前生成、可稳定调用的人物 Skill，让镜像问题能够快速形成更丰满的多人物讨论。

---

## 1. 在影子知乎中的位置

影子知乎的核心仍然是：

```text
真实知乎内容
    ↓
知乎用户 Skill
    ↓
Human Mesh
    ↓
镜像问题
    ↓
多个 Skill 分身回答
    ↓
真人查看、修改、接管或搬运回真实知乎
```

名人 Skill 不建立新的产品主线，只作为 Human Router 可以调用的另一类预置 Skill 来源。

加入后：

```text
                    镜像问题
                       │
                Human Router
                       │
             ┌─────────┴─────────┐
             │                   │
      知乎真人 Skill        公共人物 Skill
             │                   │
             └─────────┬─────────┘
                       │
                虚拟回答群组
                       │
                继续增加回答者
```

因此，用户在影子知乎里看到的仍然是同一个核心动作：

> **“我想再叫一个人来回答这个问题。”**

这个人可以是知乎真实答主的 Skill 分身，也可以是一个提前构建好的公共人物 Skill。

名人 Skill 不单独建立“名人聊天”“历史人物馆”或新的一级页面。

---

## 2. 为什么当前阶段需要它

影子知乎真正重要的技术能力，是把知乎用户过去的大量回答蒸馏成稳定的 Skill。

但黑客松阶段，如果实时抓取和蒸馏一个知乎用户需要较长时间，就会出现两个直接问题：

```text
可用真人样本数量少
+
现场生成等待时间长
        ↓
镜像问题人物不够丰富
        ↓
产品看起来像一个小型 Demo
```

公共人物 Skill 可以作为工程上的冷启动补充。

它们的资料可以提前整理、提前蒸馏、提前保存，因此在 Demo 中可以立即被调用。

这样能够保证：

```text
用户提出问题
↓
马上出现多个可选择的人物
↓
马上形成多角度回答
↓
继续添加人物
↓
镜像问题迅速变得“像一个真的知乎问题”
```

因此，名人 Skill 的主要价值不是增加一个新的产品故事，而是提高现有影子知乎的**人物密度、讨论丰富度和 Demo 稳定性**。

---

## 3. 和知乎真人 Skill 的关系

两类 Skill 共用同一种调用方式，但来源和产品意义不同。

### 知乎真人 Skill

来源：

```text
知乎用户历史回答
知乎用户文章
公开经历
历史观点
表达风格
```

作用：

```text
模拟该用户可能如何回答
帮助用户发现值得接管的新问题
最终促进真人重新创作
```

这是影子知乎的核心人物来源。

### 公共人物 Skill

来源：

```text
公开著作
公开采访
公开演讲
可靠公开材料
知乎相关讨论
```

作用：

```text
补充镜像问题的观点类型
提供稳定的预置人物
降低 Demo 对实时蒸馏的依赖
让新用户立即理解 Skill 调用机制
```

这是辅助人物来源。

因此产品上应保持：

```text
知乎真人 Skill > 公共人物 Skill
```

名人 Skill 可以让产品更丰满，但不能让用户误以为影子知乎的核心是“和名人聊天”。

---

## 4. 产品呈现方式

名人 Skill 不增加单独入口。

它直接出现在镜像问题的「Skill 阵容」或「+ 邀请一个分身回答」中。

例如：

```text
+ 邀请一个分身回答

知乎答主
@AI产品经理A
@校招HR B
@创业者C

公共人物
Elon Musk
Peter Thiel
Steve Jobs
```

用户选择 Elon Musk 后，不直接调用一个笼统的“马斯克人格”，而是根据当前问题匹配最相关的 Skill。

例如问题：

> 为什么一个硬件产品成本一直降不下来？

系统匹配：

```text
Elon Musk
└── 制造成本拆解 Skill
```

然后将这个 Skill 作为一个新的回答者加入镜像问题。

页面最终仍然保持知乎式结构：

```text
问题

回答 1
知乎答主 A · AI 产品 Skill

回答 2
知乎答主 B · 创业 Skill

回答 3
Elon Musk · 制造成本拆解 Skill
[公共人物 · AI 推演]

回答 4
知乎答主 C · 供应链 Skill
```

公共人物只是回答者阵容中的一种节点。

---

## 5. 名人 Skill 的定义

名人 Skill 不等于人物标签，也不等于完整人格。

一个 Skill 表示：

> **从某个人已有公开内容中归纳出的、可以用于处理某一类问题的观点或判断能力单元。**

例如：

```text
不建议：
Elon Musk · 制造业
```

“制造业”只是领域。

更合适：

```text
Elon Musk · 制造成本拆解
```

Skill 描述：

> 在分析制造问题时，倾向从材料、零件、生产步骤和物理约束重新拆解成本，并优先寻找可以删除或简化的部分。

因此一个公共人物可以拥有多个 Skill：

```text
Elon Musk

├── 制造成本拆解
├── 第一性原理分析
├── 高风险工程项目判断
├── 快速工程迭代
└── 长周期技术投入
```

Human Router 根据当前问题，只调用其中相关的一个或少数几个 Skill。

---

## 6. 数据结构

公共人物 Skill 与知乎真人 Skill 尽量使用相同的数据接口，方便前端和 Router 统一调用。

示例：

```json
{
  "person_id": "elon_musk",
  "person_name": "Elon Musk",
  "person_type": "public_figure",

  "skill_id": "manufacturing_cost",
  "skill_name": "制造成本拆解",

  "description": "从材料、零件、生产步骤和物理限制重新拆解制造成本。",

  "applicable_topics": [
    "制造",
    "成本",
    "工程",
    "供应链"
  ],

  "reasoning_pattern": [
    "确认真正不可改变的约束",
    "拆分实际成本",
    "删除不必要零件或步骤",
    "简化后再进行自动化"
  ],

  "evidence": [
    {
      "source": "公开采访",
      "summary": "..."
    }
  ],

  "confidence": 0.91
}
```

与知乎真人 Skill 的主要区别只有：

```text
person_type = zhihu_user
或
person_type = public_figure
```

这样不需要额外开发一套人物系统。

---

## 7. 回答生成方式

名人 Skill 被加入镜像问题后，仍然使用影子知乎现有回答生成逻辑。

输入：

```text
当前问题
+
人物
+
被选中的 Skill
+
Skill 相关公开证据
```

输出：

```text
一篇独立的知乎式虚拟回答
```

但公共人物回答需要明确标记：

> **公共人物 Skill · AI 基于公开资料推演**

不能把生成内容包装成该人物真实说过的话。

如果某个判断存在直接公开材料，可以引用或概括已有观点。

如果人物从未直接讨论当前问题，应表达为：

> 基于其公开内容中反复体现的「制造成本拆解」思路，将这一方法应用到当前问题，可以得到……

避免表达为：

> 马斯克认为……

---

## 8. 和多人物讨论的结合

公共人物 Skill 可以与知乎真人 Skill 混合出现在同一个镜像问题中。

例如：

> 普通本科生现在还值得进入 AI 产品行业吗？

回答阵容可以是：

```text
知乎 AI 产品经理 · 一线工作经验
知乎校招 HR · 招聘门槛
知乎应届生 · 求职经历
Peter Thiel · 非传统职业路径
Steve Jobs · 产品创造
```

这时产品的重点仍然是：

> 同一个问题被不同的人、经历和思考方式共同回答。

公共人物负责补充明显不同的思考框架，知乎真人负责提供当前、具体、真实的一手经验。

两者混合后，镜像问题会比单纯调用几个名人更接近知乎真实社区。

---

## 9. 当前阶段的弱化原则

名人 Skill 在影子知乎中应主动控制存在感。

它不作为：

```text
独立一级页面
独立产品名称
首页核心卖点
Human Mesh 的主体
Human API 的替代品
完整数字人系统
```

首页和产品说明仍然优先强调：

> 调用知乎用户 Skill，让没有回答的问题先在影子知乎发生一次。

只有在介绍可选回答者时，再说明：

> 为了丰富冷启动讨论，也可以加入预置的公共人物 Skill。

因此它在产品叙事中属于：

```text
核心机制：Skill 调用
        ↓
核心人物：知乎用户
        ↓
补充人物：公共人物
```

---

## 10. P0 实现方式

黑客松阶段不实时蒸馏公共人物。

采用：

```text
提前选人物
↓
提前搜索公开资料
↓
生成 Skill
↓
人工快速检查
↓
保存 JSON
↓
Demo 直接调用
```

建议只准备少量差异明显的人物。

例如：

```text
Elon Musk
Steve Jobs
Peter Thiel
Sam Altman
鲁迅
王阳明
```

每个人准备约 4—6 个 Skill 即可。

它们与知乎真人 Skill 一起进入统一的 Skill Retrieval。

---

## 11. P0 前端最低要求

现有页面只增加两处。

第一处是在：

```text
+ 邀请一个分身回答
```

中增加：

```text
公共人物
```

分类。

第二处是在公共人物回答旁增加：

```text
公共人物 Skill
AI 基于公开资料推演
```

标记。

不需要增加其他页面。

如果已有 Mesh 可视化，也可以展示公共人物自己的 Skill Mesh，但它只作为人物详情的视觉补充，不进入当前主流程的开发优先级。

---

## 12. 当前版本的完成标准

这个模块做到以下程度即可：

```text
4—6 个公共人物
↓
每人 4—6 个 Skill
↓
与知乎真人 Skill 使用统一数据结构
↓
镜像问题可以添加公共人物
↓
Router 自动选择相关 Skill
↓
生成一篇带明确 AI 推演标识的回答
```

做到这里，公共人物 Skill 已经完成它在影子知乎当前版本中的任务：

> **在不改变核心产品结构的情况下，让有限的真人 Skill 样本也能形成一个足够丰富、稳定、可玩的影子知乎。**
