# 答主可信度升级验收

## 行为与兼容

邀请接口保留旧字段，新增可选 validSamples 与 failureReason。失败原因：config、search_failed、no_match、no_valid_content、model_failed、invalid_format。
有效样本须具有至少 40 字正文及 HTTP(S) 来源链接，按 URL 去重后最多使用 5 条；1 条为 low，2–3 条 medium，4–5 条 high。这是样本覆盖等级，不是人格准确概率。昵称匹配不能排除同名作者，来源供用户核对，不作为身份认证。
格式错误最多增加一次修复调用，复用 zhidaText 的消息缓存；不重新检索。失败保留有效来源，不写模型原始输出或上游错误到日志、响应。
PersonaCorpus 的 status/note 可选，兼容旧记录。旧数据 real=false 且 capturedAt 非空时显示“人格提取未完成”，不冒充预置风格。

## 110 秒演示分镜

沿用页面现有配色和 Motion 节奏。video-talkcraft 仅用于分镜，每段以真实浏览器操作为主体，不合成操作成功画面。

| 时间 | 真实操作 | 讲解重点 |
|---|---|---|
| 0–15 秒 | 输入“35 岁该留在熟悉的岗位，还是转行？”并选三位预置分身 | 这是 AI 分身，不是作者本人参与；预置设定未经本人语料验证 |
| 15–40 秒 | 等待生成，比较三篇回答 | 等待不伪装成完成；区分表达方式与观点依据 |
| 40–55 秒 | 展开人格依据，打开一条回答来源再返回 | 人格来源解释表达，回答来源支撑观点 |
| 55–80 秒 | 追加一位分身 | 只生成新分身，保留前三篇；降级时照实展示 |
| 80–100 秒 | 进入缺口补充页，输入明确标为“演示输入”的个人判断并提交 | 真人补充提供 AI 缺少的信息，不冒充答主经历 |
| 100–110 秒 | 查看 Mesh 更新并刷新 | 展示状态保存；整理内容可复制到知乎，由用户自行发布 |

若真实等待超出 120 秒，可剪掉等待段并标注“等待已缩短”；不得剪掉失败后伪装成同一次成功。录制前隐藏凭证与个人后台，不将截图串联冒充录屏。
