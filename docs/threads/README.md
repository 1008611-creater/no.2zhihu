# 线程状态板（谁在做什么）

> 目的：让「谁在改什么」变成**可读、可验证的事实**，而不是靠记忆和口口相传。

## 为什么需要它

多线程并行时，最贵的事故不是冲突，而是这两类：

1. **重复劳动** —— 实测（2026-09-15）：审计线程提的 PR 因「不知道别人已经做了同一件事」
   而白费；开发线程改 CI 时基于过期 base，差点回退别人 32 行。
2. **基于过期信息做决定** —— 同一天里，多个线程用陈旧的本地 clone 得出了错误结论
   （「脚本不在 main 上」「这个文件不存在」），而真实情况相反。

冲突至少会报错；上面两类**不报错**，只会让人做无用功或做错判断。

## 机制：一个线程一个文件，走 git

```
docs/threads/
  README.md        ← 本文件（规范）
  _template.md     ← 新线程复制它
  <线程名>.md      ← 每个线程自己的声明
```

- **一个线程 = 一个文件** → 不会互相写入冲突（不要搞成一个共享的大文件）
- **走 git（PR 合并）** → 有历史（谁改的、什么时候）、有冲突检测、跨机器可读、可被审计
- **内容极简**（见模板）→ 越短越不容易腐化
- **超过 24 小时未更新 = 视为失效**，任何人可以删掉该文件

## ⚠️ 为什么不建一个「本地共享目录」

本地共享目录（如 `E:\codex\_devwork`）适合放**临时产物和日志**，
不适合放**权威状态**，因为：没有历史、无法判断谁改的、换台机器就不通、
而且最终一定会像 `.tools/` 那样越堆越乱。

**分工**：权威状态 → 仓库 `docs/threads/`；临时产物/日志 → 本地工作区（不进仓库）。

## 怎么用

1. **开工前先读别人的**：看 `docs/threads/` 里有没有人正在改你要改的文件 ——
   这比 `preflight.mjs` 更早一步（那个只看已提的 PR，这里看**在做的**）。
2. **开工时建自己的**：复制 `_template.md` 为 `<你的线程名>.md`，填好，
   随你的**第一个 PR** 一起提。
3. **变更时更新它**：换分支、改基线、加减正在改的文件 —— 在**同一个 PR** 里更新这一个文件。
4. **收工时**：状态改成「已合并」；或直接删掉该文件（推荐，保持目录干净）。

## 与现有机制的关系（互补，不重复）

| 机制 | 回答的问题 | 时点 |
|---|---|---|
| `docs/threads/`（本目录） | **谁**在做，正在改哪些文件 | 开工时 |
| `scripts/preflight.mjs` | 我的改动与**在途 PR** 是否重叠 | 提 PR 前 |
| `scripts/pr-queue.mjs` | 在途 PR 有几个 | 提 PR 前 |
| `scripts/verify-merge.mjs` | 合并会不会回退别人的内容 | 提 PR 前 |
| 审计线程 | 改动对不对、有没有踩铁律 | 合并前 |

## 一条硬规则

**声明与实际不符 = 比没有声明更糟。** 所以：
- 你声明的工作区/分支/文件，**必须真的存在**（审计线程会抽查）
- 长期不更新的声明会被清理 —— 宁可删掉，也不要留一份骗人的
