### 教训（三条，按有效性排序）

1. **「提 PR 前查队列」查的是「已提」的 PR** —— 而重复的高发区是
   「**正在做但还没提**」的窗口期（这次就是）。`docs/threads/` 声明能对冲，
   但前提是**对方先读**。我写了「正在改 `lib/domain/library.ts`」，仍然撞上。
2. **认领 issue 前先看 issue 上有没有别人说「我来做」** —— issue 写「交给开发线程」
   时，每个开发线程都会理解成自己。**建议：issue 上认领要留一句话**。
3. **产出被重复时，先把对方的工作独立验证一遍再关自己的** ——
   不要只凭描述就撤（万一对方有漏洞，撤错了才是真损失）。
   我这次用**全量 22 场差分**独立验证了 #74（结论一致：差异恰好 1 处，其余 21 场零变化），
   并把复核记录留在了 #74 上。
